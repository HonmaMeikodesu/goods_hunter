# Lashinbang（らしんばん）谷子监控接入调研

调研日期：2026-10-26（Asia/Shanghai）。范围：官方公开资料、匿名页面读取与本地历史样本；仅调研，不实现、不部署、不创建任务。以下区分官方事实、本次观察和工程建议，搜索引擎索引不代表当前浏览器或生产 FC 已能访问。

## 初步结论

**商品模型适合纳入 goods_hunter，但当前还不能认定可运行接入。** 官方页面具有商品编号、详情链接、价格、品相、店铺与库存，并存在同款多条销售记录；实际浏览器遇到 403，搜索结果、排序和分页尚未验证。现有 FC 浏览器与主服务定时、MySQL 去重、邮件链路可作为后续架构候选，不能把页面结构或仓库旧 mock 当成已完成适配。

**持续自动监控有明确的官方规则障碍。** 现行利用规约第 23 条第 9 项直接列出监视工具与机器人；应先向官方确认可获准的数据接入方式，再安排运行验证。降低频率本身不能解除该项限制。[利用规约](https://shop.lashinbang.com/help/agreement)

## 3. 库存、品相与同款多记录

官方详情可显示 `used`、未开封/A/B、备注、价格、店铺、在库/品切和商品编号。A 允许轻微伤痕，B 可能有明显损伤或缺件；图片可能是样图，提醒应保留品相与备注供人工判断。[商品详情及品相说明](https://shop.lashinbang.com/products/detail/7828330)、[通販指南](https://shop.lashinbang.com/help/guide)

本次该面码集合商品的主记录为 A、品切，页面的“状態違いの同一商品”同时列出 B、オンライン、在庫あり；主记录缺货不能推断整款无货。其 JAN 为 `4999999999999`。另一款商品的同款列表可出现多个门店与品相。[面码主记录](https://shop.lashinbang.com/products/detail/7828330)、[多店多品相示例](https://shop.lashinbang.com/products/detail/6818605)

工程建议：去重应采用实际销售单位 ID；`/products/detail/{id}` 和商品编号是待验证候选，不能使用 JAN 或标题作为唯一键。还需确认一个 ID 是否会补货或复用，将“首次发现新 ID”“同 ID 从缺货变有货”“降价”作为不同事件。现行 ID 生命周期与补货行为尚未实测；页面“発売日”是商品发售日期，不能直接当本站入荷时间。

## 5. 登录、自动访问规则与频率

详情页可见访客状态，不能据此认定所有商品浏览必须登录；页面明确说明年龄限制作品需登录并完成年龄认证。普通搜索匿名可用程度、会话寿命及 FC 会话恢复未验证。[公开详情页](https://shop.lashinbang.com/products/detail/7828330)

现行规约标注日期为 **2026-09-01**。第 1 条适用于所有服务使用者；第 23 条第 9 项明确禁止使用或提供“自動購入ツール・監視ツール・ボット等”及相近自动化手段。该项没有写出个人搜货、匿名访问或低频监控豁免，也未提供可采用的每分钟/每天请求额度。[利用规约第 1、23 条](https://shop.lashinbang.com/help/agreement)

`https://shop.lashinbang.com/robots.txt` 本次未读取到有效规则正文，因此 robots 允许/禁止路径与 Crawl-delay 均未证实；robots 不可读也不能代替上述明文规约。可访问性失败的原因不能只凭 403 归因于地区、登录或反机器人机制。

## 6. 本次浏览器实测

2026-10-26 11:16（Asia/Shanghai），使用用户授权的 Playwright 在新标签页打开商城首页，并读取已加载页面；随后用本地 Python 标准库进行各一次普通匿名 GET。没有登录、修改指纹、尝试其他出口或处理安全校验。

| 途径与目标 | 本次观察 | 可支持的结论 |
| --- | --- | --- |
| Playwright：`https://shop.lashinbang.com/` | HTTP 403，标题及页面正文为 `403 Forbidden` | 当前浏览器环境未成功进入商城；未到达搜索、排序、分页操作 |
| 本地匿名 HTTP：商城首页 | HTTP 403 | 普通 HTTP 在当前环境同样失败 |
| 本地匿名 HTTP：`/robots.txt` | HTTP 403 | 没有取得 robots 正文，不能填写其规则或频率 |
| web 阅读工具：商城首页 | 读取失败，报告 403 | 不是独立的搜索采集成功证据 |
| web 阅读工具：官方商品详情、帮助及作品链接 | 可以读取部分详情/帮助正文，作品列表仅取得页面壳 | 可以查证页面字段和官方链接；不能据此认定本地浏览器或 FC 能执行搜索 |

没有确定 403 的原因，也未验证阿里云 FC 的实际出口。不能由此断言站点全球不可访问、必须登录或在日本一定可用。搜索引擎商品摘要与本次详情读取的价格还可能不同，索引不能作为实时库存/价格输入。浏览器临时记录已清理，研究文件不保存会话凭据。

## 7. FC 接入建议

### 仓库已有线索

仓库存在 [Lashinbang 历史 mock](../src/api/site/lashinbang/mock/goodsList.txt)，但该目录只有样本文件；本次源码检索未找到运行中的 Lashinbang 适配器、任务类型、模型或 Hunter 服务。这是早期调研材料，不能把它当作已支持的平台。该文件最后一次提交为 `418f8d0`，日期 **2024-08-06**。

本次离线解析得到：外层为 `kotohaco`，`result.items` 有 20 条，`result.info` 记录 29 个命中、2 页、当前第 1 页。请求记录的 host 为 `lashinbang-f-s.snva.jp`，带 `q`/`searchbox`、`sort=Score,Number7`、`limit=20`、`o=0`；关键词为“あの日見た花の名前を僕達はまだ知らない”。商品字段包括 `itemid`、`title`、`url`、`image`、`price`、`number7` 等。`number7` 的样本形似 `20240804`，但没有查证其正式语义，不能定义为入荷时间。

以上全部是 **2024 年本地历史样本**，不是今天的接口实测；没有调用该旧 host，未证实现行站点仍使用它，也未查到相应官方开放 API 契约。旧样本参数、分页和状态含义不能直接写进新采集器。[项目既有发布时间讨论](sitesWithoutPublishTime.md)也提到 Lashinbang 和按 ID 记录发现历史的方案；它是历史工程判断，不是现行站点的语义承诺。

### 可复用与需要补齐的能力

| 部分 | 工程判断 |
| --- | --- |
| FC 执行环境 | 可复用现有 Chrome/Playwright 容器基础设施。未来宜有独立 Lashinbang handler，按实际页面取数；不能直接套用 Yahoo!フリマ 的 `__NEXT_DATA__` 解析器。[现有 FC 专用采集器](../../bypass-cloudflare/yahoo_fleamarket.py#L151) |
| 主服务链路 | 可复用签名 FC 调用、任务调度、首次基线、MySQL 记录和邮件通知模式。[FC 客户端](../src/api/alicloud/index.ts)、[现有商品任务服务](../src/service/hunterArsenal/yahooFleamarket.ts) |
| 商品记录 | 候选字段为实际销售单位 ID/详情链接、标题、日元价格、品相、店铺和库存状态。商品组、销售单位和门店库存需按真实页面关联，不能默认一个 JAN/标题就是一条待售记录。 |
| 失败处理 | 明确区分有效空结果、403、登录/安全校验、列表脚本未完成和结构变化；只有完整有效的一轮采集才更新基线。失败不能清空库存或产生“重新上架”通知。 |

建议后续验证顺序：先确认获准的数据访问方式与范围，再在实际 FC 环境取得一轮有效搜索；随后验证角色/作品两种查询、排序、至少两页及不同品相记录，最后进行有限连续运行以观察补货和错误恢复。只有这些通过后再开发和注册正式任务；本轮没有调用生产 FC、改业务代码或部署。

## 8. 检索边界与待验证事项

本轮未登录、购买、执行验证码、重放内部搜索请求或进行并发/频率测试；未操作生产 FC 或注册定时任务。官方资料支持“线上销售记录、同款多库存、品相与门店”的模型，但不能证明搜索成功率、全量覆盖、实时库存或连续运行能力。当前缺口是获准接入方式、真实搜索结果结构、新着/分页/在售语义、销售单位 ID 稳定性及 FC 实际出口可达性；不应把“尚未证实”写成“绝无此能力”。
