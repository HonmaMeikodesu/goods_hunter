# Yahoo 会话告警误报与重复提醒

2026-10-30，收到“Your yahoo cookie seems to expire or invalid”重复提醒反馈。

## 脱敏证据

- 云服务器快照为 `ready`，最后验证时间 `2026-10-29T16:08:49Z`（北京时间 10 月 30 日 00:08:49）；调查时约 16 小时，主应用实际配置的有效期为 172800 秒。
- 同一应用 worker 每小时检查，检查日志没有进程反复重启迹象。
- 真实 FC 个人页检查复现 `FC_CHECK_FAILED`，底层结果为 `ERR_CONNECTION_CLOSED`，没有返回页面内容。
- 同一份导出 Cookie，在独立的 Chrome 上下文、现有代理和 HTTP/1.1 配置下通过 `wait_authenticated` 检查：个人页 URL 正确、可见认证标识存在、无登录链接；未写入 profile 或更新快照。
- 随后 FC 复查也成功，包含个人页认证标识。因此调查时 Cookie 仍有效，FC 连接有间歇故障。尚未确定连接关闭具体发生在代理还是 Yahoo 上游，未改变 FC 镜像。
- 旧通知逻辑将所有错误称为 Cookie 过期，且一次成功即清空六小时冷却。测试中的“失败→成功→失败”发送两封，复现限流缺陷。未取得逐封邮件投递记录，不能断言所有历史邮件均由此路径触发。

## 修复

- 网络、未验证页面、快照状态异常使用中性检查失败标题；明确登录要求单独提示。
- 使用 Redis `SET … EX 86400 NX`，所有实例共享一个 24 小时会话告警窗口。成功不会清除冷却，重启也不影响。
- 在发送前占用窗口；SMTP 失败保留窗口，避免发送结果不确定时重复投递。Redis 不可用时只记脱敏日志；不退回无限流发送。
- 每次心跳记录已知原因码，未知错误不输出原始内容。Cookie 每日刷新和快照 48 小时有效期不变；心跳仍每小时检查。

## 验证与部署

回归测试覆盖波动、并发实例、重启、24 小时边界、通知分类、未知原因脱敏、Redis/SMTP 故障。相关会话、搜索解析及 Yahoo Flea Market 测试 50 项通过、8 项数据库集成测试按原配置跳过；`tsc --noEmit` 通过。回环 HTTP 测试须在允许本机端口的环境执行。

部署脚本：`ops/deployment-history/local/session-alert-fix/rollout.py`。要求云端 Git 干净、main 快进、只变更本次文件；保留原运行环境，停止旧进程树、更新、启动并检查 HTTP，失败回滚。运行收据和日志留在私有部署目录，脚本本身纳入 Git。
